默认进烽火 + 每天先复习一批才开新局

产品决定三条：先弹今天该复习的错题、复习完才允许开新局、默认模式换烽火。实现时撞出一个真 bug：错题本在烽火里一直是空的。

v4.0.222026-10-18默认 = 烽火复习闸只拦第一批错题本改全局共享

一、默认进场：原来永远是闯关

// 查代码前以为「会记住上次模式」，其实不是：
const lm = localStorage.getItem('himath_lastmode');   // 只是「清档重开后回到刚才的世界」
if(lm==='blaze') useWorld(BLAZE);                    // 读不到 → 一直是 ADV

// 改后：一处决定默认
function bootWorld(lm){
  if(lm==='epic') return EPIC;
  if(lm==='blaze') return BLAZE;
  if(lm==='drill') return DRILL;
  if(lm==='adv') return ADV;
  return BLAZE;          // 没有标记（含全新玩家）→ 烽火
}
所以「一点开就是闯关介绍」是必然的，不是错觉。清档重开的标记仍然优先，闯关也没删（☰ 一键切）。

二、每日复习闸：拦什么、不拦什么

  • 开机弹：公告 / 首访说明之后才弹「今天到期 N 题」，最多等 6 秒 —— 玩家已经点进别处就放过这一次。
  • 硬闸在部署上：blazeDeploy() 第一行查 reviewNeed()，今天没复习就不让开新局；复习完成后回调部署自己，不用再点一次。
  • 完成标记写在练完之后（不是点「开始复习」那一刻）—— 半路退出，下次照样拦。
  • 每天只拦第一批（REVIEW_BATCH=10）：到期几十题时一次全拦，人会直接关掉游戏，那就连复习也没有了。
  • 只拦开新局：地图 / 菜单 / 练枪照常 —— 练枪本来就在做题。
两条分寸是我加的（你说的是「复习完才能玩」）。要更严就说：把 REVIEW_BATCH 调到 99（等于全拦），或者把闸门也挂到闯关入口上。

三、撞出来的真 bug：错题本在烽火里是空的

这个 bug 是撞在我自己写的检查上才暴露的：检查里造的到期题，一切到烽火就「消失」了 —— 于是顺着查下去，才发现错题本压根不在烽火里。

wrongBook / wrongDone 只定义在 ADV_STATE 上
全项目 99 处读写用的是 state.wrongBook —— 而 state 指向「当前世界」

⇒ 进了烽火 / 史诗 / 练枪之后：
   · 错题中心显示 0 题
   · ☰ 菜单「今日待复习 N」永远 0
   · 烽火里答错的题进不了错题本（正是复习闸要拦的东西）

改法：wbShare() —— 四个世界的 state 指向**同一份数组**（引用别名），
99 处调用一行不改；读档后按 text 去重再并一次（ADV 优先），
避免「只玩烽火」时 ADV 存档落后把新错题丢掉。

四、两处检查踩坑（都是检查写错，不是代码错）

① 假数据被 `useWorld` 换掉了： 到期题塞在 state.wrongBook 上，而 useWorld(BLAZE) 会把 state 换成 BLAZE —— 假数据跟着消失，于是「闸门没拦住」。改成塞在 ADV_STATE 上再 wbShare()。
② 把返回值当契约： 断言写成 !!blazeDeploy()，可它成功时返回 undefined（整个函数没有 return true）。改成看 BZ.active。这类假设比 bug 更容易骗人。
