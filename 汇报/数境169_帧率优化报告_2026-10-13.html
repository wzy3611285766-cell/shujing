SHUJING · PERFORMANCE REPORT

帧率优化报告

2026-10-13 · 定位到帧率瓶颈是「每帧把 2400×1900 的地形位图重贴一遍」· 改了 3 处渲染· 答题/菜单界面帧率提升 5～8 倍，地图界面提升约 1.9 倍（弱机模拟实测）

一、先说结论

帧率的锅不在题库、不在 JS 逻辑，全在渲染。实测：update() 每帧只要 0.01ms、syncEnts() 0.04ms、save() 0.00ms —— 逻辑侧几乎不花时间。而单单一次ctx.drawImage(staticLayer,0,0)（把整张 2400×1900 的地图铺到屏幕上）就要 5.8ms，占满 60fps 预算的 35%，是整帧画布开销的 90% 以上。

为什么这么贵：地形图是按「1 世界单位 = 1 像素」画的，贴到屏幕上要放大 SCALE×DPR 倍（手机竖屏 0.694×2 = 1.387 倍）。非整数倍放大时，每一个目标像素都要做一次双线性插值。同一块面积：

画什么耗时说明
纯色铺满整屏0.38ms对照基准
贴地形位图（现状）5.81ms放大 1.387 倍，逐像素插值
贴地形位图 + 关掉平滑1.23ms改成最近邻取整采样
什么都不画0.20ms

（同一批测量里还验证过：平移取整没用（6.06→6.02ms）、只贴可视区也没用（4.65→4.54ms）—— 成本只跟「要不要重采样」有关，跟贴多大面积无关。）

二、改了三处

① 面板打开时不再重画地图

地图在答题/看菜单时被压在蒙层底下，玩家根本看不见，却还在每帧重画。

function loop(now){
  const dt=Math.min(50,now-last);last=now;t+=dt;
  update(dt);
  if(!panelOpen()&&!newsIsOpen())draw();   // ← 新增这一层判断
  requestAnimationFrame(loop);
}

更关键的是：#modal 上挂着 backdrop-filter:blur(4px)，底下那张 canvas 每帧都在变，合成器就得每帧重算一次全屏高斯模糊 —— 答题时的卡顿主要来自这里。停画之后背景成了静止画面，模糊只算一次。

② 地形不再每帧「贴」，改成整层平移

新增一个 <canvas id="bg"> 专门放地形：世界画一次，之后整层靠 CSS transform 跟着镜头走。

function syncBgTransform(){
  bgCv.style.transform='translate3d('+(-cam.x*SCALE).toFixed(2)+'px,'
    +(-cam.y*SCALE).toFixed(2)+'px,0) scale('+SCALE+')';
}

合成器在 GPU 上挪一个图层几乎不要钱，主线程一分钱不花，而且是 GPU 双线性采样，比原来 canvas 那条路更平滑。#game 上只剩地面光晕、角色圈、小地图这些每帧都在变的东西。

取不到 #bg 时会自动退回原来的一次性位图 blit，功能不受影响。

③ 兜底路径关掉双线性插值

退回老路径时，放大倍率 ≥1 就改用最近邻采样（5.8ms → 1.3ms）。倍率 <1（桌面窄窗口这类缩采样）时最近邻会丢像素、走起来闪烁，所以那种情况保留平滑。

三、优化前后帧率（弱机模拟实测）

测法：软件光栅（--disable-gpu）+ CPU 降频 6 倍，模拟一台弱手机；每个状态采 3 秒的 rAF 帧间隔。同一台机器、同一套操作，只换 HTML 文件。

要诚实说清楚两件事：
1. 这是软件光栅模拟，绝对帧数不代表你的手机；真机有 GPU，合成那步基本白送，所以实际会比表里好看。
2. 横屏地图那一档我没测出改善（噪声比差异还大）。原因是模拟环境里「软件合成多张全屏图层」成了新的天花板，把画布省下的那点掩盖了。真机上这一步走 GPU，理论上不该是瓶颈 —— 但这一条我没有证据，不敢替你保证。
