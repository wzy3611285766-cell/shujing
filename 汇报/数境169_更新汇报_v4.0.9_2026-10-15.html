一、现在的开场规则（四种情形）

玩家情形开场看到什么为什么
全新玩家（本机什么都没有）只弹「闯关模式说明」，出现一次，点掉就记下他连上次是什么样都不知道，先糊一张「本次更新」没有意义 —— 公告直接记为已读
老玩家 + 这版公告没看过弹更新公告，不弹说明老玩家要的是「这次改了什么」
老玩家 + 公告看过了开场干净，只剩顶栏一句「今天有 N 道错题到期」同一个公告不该反复糊脸
手里是旧版（缓存里那份）顶部更新通知栏每次打开都提醒，列着新版改了什么，点「立即刷新」换上新版他还没拿到新版，提醒到刷新为止
「教学只出现一次」靠的是写进本机的已读位（<世界>_intro）。修之前这个已读位从来没被写下来过 —— 这就是「每次都弹」的全部原因。

二、根因：两个同名函数，覆盖的那份漏了写入

maybeIntro() 在源码里定义了两份：55_boot_news.js 一份、69_blaze_toggle.js 一份。同一个脚本作用域里，后面那份把前面那份整个盖掉，所以真正生效的是 69 那份。而它有两个致命的小疏漏：

  • ① 「读过了」的标记从来没写：闯关分支结尾只写了 closePanel，没写已读位。
  • ② 兜底也失效：它把 introShowing 留在 true，于是 openPanel 里那条「说明面板被别的入口顶掉也算读过」的兜底永远不触发。
  • 两头都断了 → 每次打开都当你是第一次来。修法：两份合并成一份（留在 55_boot_news.js，四个世界的说明都在那里处理），点掉就写已读位。
// 69_blaze_toggle.js（当年真正生效的那份）
function maybeIntro(delay){
  try{if(localStorage.getItem(curKey+'_intro'))return;}catch(e){return;}
  setTimeout(()=>{
    ...
    if(html){ openPanel(html); ... return; }
    /* 闯关模式的说明 */
    openPanel(`...`);
    $('go').onclick=closePanel;        // ← 漏了写 localStorage[curKey+'_intro']='1'
  },delay||0);
}

三、顺带把判定改对了：看「有没有玩过」，不看标记

老玩家本机从来没有那个标记（就是上面这个 bug 造成的）。如果只认标记，修好之后所有老玩家会被再糊一次说明。所以新增 isNewPlayer()：答过题（≥3）或有精灵 / 徽章 / 错题本 / 卷宗 / 答题流水，才算玩过；老玩家静默补上标记，不再弹。

这里踩过一个坑，记在注释里了：第一版把 state.tier 也算进「玩过」的证据，但 healState() 会给每个域都塞上 tier:1（那只是初始化，不是玩过）—— 结果所有新玩家都被判成老玩家，公告照样弹。是跨进程的真实开场测试把这个假阴性抓出来的（冒烟那条当时是在一页之内模拟的，没走 healState，反而「通过」了）。冒烟那条现在也补上了 healState()，跟真实开场一致。

四、怎么验的

① 冒烟新增永久检查「首访说明只弹一次」： 真造三种玩家（全新 / 已读位在手 / 有进度），逐项断言弹不弹，并且验已读位到底写没写进去 —— 只验「弹了」是抓不住这个 bug 的。
② 真实开场探针（一次性）： .tmp_play/_two_boot.py 把「种子」脚本插在 <head>（赶在游戏脚本之前写好 localStorage），三种玩家各跑一次真页面加载。结果：全新玩家弹说明不弹公告 · 已看过说明的不弹说明只弹公告 · 有进度的老玩家不弹说明只弹公告，三种全部符合预期。
③ 为什么不用「连开两次浏览器」： headless 退出时 localStorage 不保证落盘，两个进程共 profile 会假阴性（第一次试就是被这个骗了）。改成页内真实重载 + head 预置，验的是同一套启动代码。
