## 数境 169 版：烽火地带战场底图重做

**任务**：用户反馈「烽火地带的背景贴图太乱」，要求优化地图（并要求改完自己反复测到满意）。

**产物**：仍就地改 `C:/Users/Lenovo/Desktop/数境/数境169.html`。截图存 `shots_blaze/`。

### 诊断（关键判断）

用户说的是"贴图太乱"，但**根因不是细节多，而是没有视觉层次**：
七层纹理（底色渐变 + 军事网格 + 满屏扫描线 + 焦土斜线 + 栅格线 + 掩体 + 装饰）全挤在同一个明度区间；
更要命的是**全画面都挤在蓝色系**——地面 `#3d4f74`（饱和 47%、亮度 45%）、建筑墙 `#2b3546`、
掩体 `#405066`、河青、装饰浅蓝，八样东西同色相，只能靠 2px 描边区分。

### 改动（按"地面退到后面"一条原则）

1. **扫描线彻底删掉**（简洁档 + 完整档都不画）：满屏等距横条纹是最大噪音源，缩放后还起摩尔纹。
2. **坐标网格** 168px→240px、浓度 .035→.030；**焦土斜线** 64px→96px、浓度 .035→.018。
3. **地面三色全线压暗去饱和**（BLAZE_SITES.ground）：math `#3d4f74/#1d2942` → `#2b3653/#161d2c`，phys/chem/bio 同样处理，保留各自色相。
4. **实体全部从蓝色系拉出，走中性灰阶**：建筑墙 `#2b3546` → `#414a56`（并提亮描边 .14→.20）；
   建筑地板从"rgba(0,0,0,.34) 叠在蓝地面上"（=更深的蓝）改成**实色** `rgba(26,30,37,.92)`（vault 房用暖棕）；
   掩体与岩石统一中性灰。
5. **掩体立体化**：旧版是"深色地面上再压一层黑"= 一滩污渍。新版三条一起立：投影离地 + 三段渐变（顶亮底暗）+ 顶沿一线冷光。
   注意**不要用"纯色块 + 一条高光带"**——那条带子近景看就是一横白线，像贴着纸条；亮段必须写进渐变里。
6. **装饰（drawProp）密度砍到 1/3**（12000→34000，约 129→46 个）、透明度 .09~.19→.05~.11，从"撒满"退成"点缀"。
7. **道路中心线从黄虚线改成白色实线**：图里虚线已被三处占语义（战场边界、POI 圈、撤离点圈）全表示"范围"，
   道路再挂黄虚线就是第四种虚线，眼睛没法靠线型判断。现在 **虚线=范围，实线=实体**。
8. **新增地表纹理层**：18 个柔斑（隆起/凹地）+ 细网格，画在**战场 poly 内部**（clip 到边界）。

### 踩到的两个真坑

- **纹理画错层 = 白画**：第一版把斑块和网格留在全局层，而战场地面是**不透明**渐变填充 —— 全被盖掉，
  截图里一个都看不见。必须移进 `REGIONS.forEach` 里、紧贴地面填色之后。**（教训：改绘制顺序前先确认谁盖谁）**
- **斑块半径太小 = 看出是圆圈**：半径取短边 18%~48% 时圆心和边缘同时进画面，基地那张小图上像"水面油渍"。
  改成 32%~74% 让**边缘出画**，透明度降到 1.4%~5.4%，剩下的才只是"这片比那片亮一点"。

### 验证（4 轮迭代 + 全覆盖）

- 第一版：删扫描线 + 径向底色 → 掩体太亮（37% 比建筑墙 29% 还高），抢戏
- 第二版：掩体降亮、斑块增强 → 发现斑块被地面覆盖（白画）
- 第三版：纹理移进 poly → 掩体高光带太硬
- 第四版：掩体改渐变 → **四战场（数学/物理/化学/生物）逐一部署截图**，配色全部成立
- 收尾：大厅（无 poly 分支）也补上纹理，保持两分支观感一致；斑块半径修正
- **性能**：建图 20~28ms（一次性离屏渲染，不影响帧率）；部署全程 ~200ms；**0 控制台错误**
- 文件从 1,585,378 → 1,635,220 字节

## 数境 169 版：烽火经济平衡 + 大厅交互重构

**任务**：① 算清烽火模式每小时能赚多少金币，调整爆率、把升级速度控制到"摸金游戏"的手感；② 审查所有按键的位置、互动顺序与必要性。

**产物**：仍就地改 `C:/Users/Lenovo/Desktop/数境/数境169.html`。

### 一、经济：先量再改（400 局成长模拟）

用游戏真实掉落函数（`blazeRollInto`/`rollRarity`/`makeLoot`）写成长路径模拟，模拟玩家"逐局选难度 → 买装备 → 跑图 → 撤离 → 卖货 → 升部门"。

**改前基线**：每局净赚 ~290，**每小时 2488**，400 局还没点满（约 50 小时）。

**发现一个真设计倒挂**：`BLAZE_DIFF.sig` 是 4/3/2 —— **难度越高容错越少，但题目越难、错题率越高**。
高考场开满 12 个箱子，75% 正确率下阵亡概率 **84%**，期望收益变负数，高难度区成了没人敢进的陷阱。
摸金游戏是反过来的：绝密图给更好的护甲/更多容错，风险来自"敌人更强"而非"你自己更容易死"。

**四处改动**：
1. `sig` 4/3/2 → **5/6/7**（题目越难，越要多给容错）
2. `BLAZE_SELL_RATE` 0.40 → **0.65**（摸金游戏商人收货 7~9 折；0.40 把整条成长线一起砍了，卖货也没爽感）
3. `mul` 1.0/1.5/2.1 → **1.0/1.7/2.6**（高难度必须明显更值，才对得起风险）
4. 部门成本 12.46 万 → **22.47 万**（各级 ×1.8 左右；前期 2200~3400 仍旧便宜，顶级 27000~38000 当长期目标）

**改后（同一模拟）**：**108 局 / 24 小时点满**，每局毛收入 5356、每小时 19674。
分档收益：常规 ~3000/小时、中档 ~8000/小时、高考 ~19000/小时（毛）；净约 12800/小时。
**为什么不一味砍收益**：砍了每局又没收获感，玩家只会觉得白打 —— 拉长升级线才是对的做法。

### 二、大厅交互重构（这是"按键"问题的真正所在）

**实测数据**：大厅总滚动高 **2972px**，面板可视只有 **716px** ——
玩家要做完「选地点 → 选难度 → 勾装备 → 按部署」，得往下滚 **4 屏**，
而最关键的「🚀 部署行动」还压在最后一屏的最底下。

**改法（纯布局，所有 id 与事件绑定原样保留）**：
- 地点 4 张 → **2×2 网格**（去掉 brief，挪进 `title`）
- 难度 3 档 → **三列并排**，压成"图标/名称/倍率/门槛/规模"五行小卡
- 携带物资 11 件 → **三列网格**（效果说明不写在卡里 —— 下方"携带加成"汇总区已经逐条列了）
- 携带中的装备**整卡点亮**（绿框）
- **底部「战备采购 / 部署行动」吸底**（`position:sticky`）
- 结算界面的三个按钮同样吸底（原来要滚到底才看得到）

**结果**：2972px → **1660px**，部署键从"第 4 屏底部"变成 **y=711 常驻可见**。

**其它审查结论**（保持不改的）：
- 战场 HUD 布局本来就对：左手摇杆（148×148 @ 左下）/ 右手互动键 / 顶部 4 个 chip / 目标条
- 互动顺序合理：地点 → 难度 → 装备 → 部署
- 结算的「💱 去交易站卖掉」只在有战利品时出现（条件显示正确）
- 6 个页签、战场按钮都必要，**没删任何按钮**
- **PC 上两处重复提示**已修：`moveHint` 原本讲 WASD/E（与左下角 `pcHint` 重复），改成只留"点地图任意位置，自动走过去"这句别处没有的

**验证**：8 个大厅按钮逐个点击回归全部生效（选地点/选难度/勾装备/切跑刀/切页签），`val 640 < 700 → 部署键正确禁用`，0 控制台错误，`SYNTAX OK`。

### 关键经验

- **改数值前先建可运行的模拟**。这次全靠模拟才定位到"信号值倒挂"——光读代码看不出"84% 阵亡"这种事。

- **吸底操作栏**是长面板的通用解法：核心动作（部署/结算）不该被滚动条锁在最后一屏。

## 数境 169 版：练枪入口解绑（不再需要先回闯关）

**任务**：用户反馈「练枪是一个快速训练自己的功能，不应该切到闯关之后才能使用」。

**产物**：仍就地改 `C:/Users/Lenovo/Desktop/数境/数境169.html`。截图 `shots_drill/`。

### 根因

`showDrill()` 开头有一道拦截：

```js
if(CUR!==ADV&&CUR!==DRILL){ /* 弹一块"先回闯关"的指路牌 */ return; }
```

注释里给的理由是"史诗与烽火各有自己的 state，混进去会污染统计"。
于是顶栏那颗 🎯 明明亮着，在烽火/史诗里按下去只得到一句"回去再说"。
菜单里的入口更彻底 —— `${!bz&&!ep? ... :''}`，**在史诗和烽火下直接不渲染**。

### 为什么不能就地开面板

练枪要写三本账（`state.drill[]` 练题流水 / `state.drillTopic[]` 上次专题 / 错题本），而 `state` 是跟着世界走的。
就地打开会把练题数据写进史诗/烽火的进度里。所以**必须真的切世界**，这不是偷懒。

### 改法（最小改动，不动既有行为）

1. `showDrill()`：史诗/烽火下改为 `switchTo(DRILL)` 直接把玩家送进练枪场，然后继续开大厅；
   切完给一条 toast 说明"☰ 菜单可切回原来的世界"。
   **加了一道保险**：`switchTo` 遇到"有题正在作答"会拦下并 return，此时 `CUR!==DRILL`，
   必须 `return`，否则就会在烽火的 state 上打开练枪。
2. 菜单入口（两份 `showMenu`）去掉 `!bz&&!ep` 条件，**始终显示**；
   描述里的"已练 N 题"改成只在 `CUR===ADV||CUR===DRILL` 时显示（别的世界下那个数字读的是那边的账，不准）。
3. 顺带修一处文字撞车：烽火下 `btnMode`（模式切换键）文案原本也是「🎯 练枪」，
   和常驻的 `#btnDrill` 一字不差，改成「🎯 练枪场」以区分"切换世界"与"打开训练"。

### 验证（5 个场景全过）

| 场景 | 结果 |
|---|---|
| 烽火里点 🎯 练枪 | 世界切到 drill + 打开练枪大厅 ✓（旧版弹"先回闯关"） |
| 史诗里点 | 同上 ✓ |
| 闯关里点 | 世界仍 adv，直接开大厅 ✓ **行为保持不变** |
| **答题中（panel lock）点** | 被正确拦住，toast「先把这道题做完」，世界仍是 blaze ✓ |
| 解锁后再点 | 正常切过去 ✓ |
| 控制台错误 | 0 ✓ |

**额外验证了"切走不丢进度"**（这是最该担心的）：烽火部署 → 背包 5 件（估值 153）→ 点练枪切走 →
`BLAZE_STATE.run` 仍存着 5 件 → 切回烽火 → `phase: search`、背包 5 件、估值 153、`BZ.active: true`，
**与切走前完全一致**。（靠的是 `switchTo` 里既有的 `blazeSaveRun()`。）

### 经验

- **入口的"守卫条件"要区分两种**：一种是真的不能做（数据会串），另一种只是"路径没铺好"。
  这里是前者 —— 但正确解法不是"把玩家挡回去"，而是**替他把世界切好**。
- 加新流程前先读一遍目标函数的既有逻辑：`switchTo` 末尾本来就有"切到练枪场后自动开大厅"
  （带 `panelOpen()` 保护），所以我的调用不会造成双重弹出。

## 数境 · 4.0.3：修「公告不弹」+「没声音」两个 bug

用户报：「进入游戏不弹更新公告，音效必须手动重开一遍才能有声音」。两个 bug 是**连着的**。

### 🐛 公告不弹

`NEWS_VER='v173'` 是硬编码的"已读位"版本号，**后面几版都没升过**。
玩家看过一次就写进 `localStorage['genji_news']`，值不变就永远不再弹 —— 新公告写了也发不出去。

修：升到 `'v4.0-1012'`，把公告内容换成本次更新（母题阶梯 + 实验题 + 修 bug），
并在常量上方加了醒目注释「⚠️ 发版必改」。**以后每次写公告必须同时改这个值。**

### 🐛 进游戏没声音（根因很有意思）

`showNews()` 里有 `try{SFX.unlock();}catch(e){}` —— 注意 **`SFX.unlock` 是一段"解锁/升档"音效，
不是解锁函数**（真正的解锁函数叫 `audioUnlock()`，名字撞了）。于是：
公告在**玩家第一下手势之前**就弹出来 → 播那段音效 → `tone()` → `audioCtx()` 把 AudioContext
**创建成了 suspended 状态**。

而旧 `tone()` 只检查 `ctx.state==='closed'`，**不检查 suspended**：
suspended 时 `ctx.currentTime` 不前进，所有音符全堆在同一个 t0 上，
等真解锁时一股脑炸出来（听着像噪音）或者干脆不出声。
玩家得碰巧点到某个会调 `audioKick()` 的按钮才 resume —— 而开局第一下点的往往不是那种按钮。

**修了三处**：
1. `tone()` 加守卫：`if(ctx.state!=='running'){audioUnlock();return;}` —— 冻结时不排音符。
2. `audioUnlock()` 放宽：不只在 `suspended` 时 resume，且给 resume 的 promise 挂 `.catch` 静默吞掉拒绝。
3. **挂全局首次手势解锁**：`pointerdown/touchstart/mousedown/keydown`（capture 阶段）
   第一下就把上下文解锁，解锁成功后自己摘掉监听。不再依赖"哪个按钮碰巧调了 kick"。

**实测**：老存档（`genji_news=v173`）进游戏 → 公告弹出 ✓ → 点关闭 → 已读位写成 `v4.0-1012` ✓
→ 再进不弹 ✓；音频 `载入后 suspended → 首下手势后 running` ✓。

**教训**：命名撞车（`SFX.unlock` vs `audioUnlock`）害人不浅；另外凡是"只在某些入口里调用"
的初始化逻辑，都要想一遍"玩家第一下点的不在那儿怎么办"。
