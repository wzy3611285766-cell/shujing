## 数境169 · 帧率优化（用户："现在这游戏的帧率太低了，咋才能把帧率提升一点？"）

### 定位过程（先测再改，别猜）
- 逻辑侧先排除：`update()` 0.01ms/帧 · `syncEnts()` 0.04ms · `save()` 0.00ms · `updateHUD()` 0.14ms。
- PC headless 环境有巨大余量（144fps、所有界面状态都不掉帧）→ **PC 上复现不出卡顿**。
- 用「软件光栅 + CPU 降频 6 倍」模拟弱机才复现：原版地图 8.7fps、答题面板 10.8fps。
- 逐项 A/B（同一批测量、轮询取最小值）锁定瓶颈：
  | 画什么 | 耗时 |
  |---|---|
  | 纯色铺满整屏 | 0.38ms |
  | 地形位图整图 blit（现状） | **5.81ms** |
  | 同上 + imageSmoothingEnabled=false | 1.23ms |
  | 什么都不画 | 0.20ms |
  关键结论：**成本只跟「要不要重采样」有关**，跟贴多大面积无关。
  平移取整（6.06→6.02）、只贴可视区（4.65→4.54）都没用；
  预缩放图 1:1 + 整数偏移能降到 1.32ms。
  为什么贵：地形图按 1 世界单位=1px 画，贴屏要放大 SCALE*DPR（竖屏 1.387）倍，逐像素双线性插值。

### 改的三处（数境169.html）
1. `loop()`：`if(!panelOpen()&&!newsIsOpen())draw();` —— 面板打开时不重画地图。
   连带收益：`#modal` 的 `backdrop-filter:blur(4px)` 不再每帧重算（底图静止了）。
2. 新增 `<canvas id="bg">` DOM 层装地形，世界画一次，之后靠 `syncBgTransform()` 写
   `translate3d(-cam.x*SCALE, -cam.y*SCALE,0) scale(SCALE)` 跟着镜头走。
   `#game` 只剩光晕/角色圈/小地图。CSS 要给 `#game{position:relative;z-index:1}` 才不会被 #bg 盖住。
3. `draw()` 里保留兜底：`staticLayer===bgCv` 时走老 blit + 关平滑（倍率≥1 才关，缩采样保留平滑）。

## 数境169 · 账号系统与跨设备云同步（用户："做一个账号系统，登录就能同步数据"）

### 云服务（WorkBuddy 内置后端）
- 应用：`wbapp_5b1uGj28EZC4FoiTkHB5Do`（appName 数境，domainPrefix `shujing`，web）
- 域名 `shujing.app.workbuddy.host` · oauthRelayBaseUrl `https://www.workbuddy.cn/v2/as/genie-baas/oauth`
- 数据表 `saves`：`id / owner_id(DEFAULT auth.uid()) / owner_name / payload / saved_at / device /
  created_at / updated_at`，`owner_id` 上有唯一约束（一个账号一行）。
- RLS 四条策略 `saves_{select,insert,update,delete}_own`，owner-only；grant 给了 authenticated,anon。
  **实测：未登录读库返回 [] 且 error=null（RLS 生效）**。
- **微信登录开关是开着的**（`signInWithOAuth` 返回了真实 authorize URL）。手机短信未验证（不能拿别人的号发短信）。

### 代码结构（`shujing-app/index.html`）
- 云存档模块追加在原 `<script>` 的**最末尾**（约 1.9 万字符），必须放在同一个 script 里才能
  访问 `state` / `save` / `openPanel` / `esc` / `$` 这些顶层 `const`（不在 window 上）。
- 入口：`showAccountPanel()`；菜单项 `#mAcct` 已加进**两个 showMenu 模板**并各自绑定。
- **`save` 是函数声明，被整体替换成包装版**（`const _save=save; save=function(){...}`），
  用来挂本机存档时间戳与脏标记。改 save 时要记得这一层包装。
- 同步键前缀 `genji_` / `himath_`；本机元数据用 `shujing_` 前缀（不进云）。
- 覆盖云端前先备份到 `shujing_prev_local`，面板有「撤销上次覆盖」。

### 硬约束（务必记住）
- **登录只认发布域名**：`cloudWhy()` 判断 `location.protocol==='file:'` 或 hostname 不匹配时，
  一个远端请求都不发，面板直接说明原因。所以 file:// 双击打开的版本永远用不了登录。
- 只有发到 `shujing.app.workbuddy.host` 上，账号功能才生效 —— 这也是"待发布"的原因。

### ⚠️ 踩到并修掉的安全漏洞（重要教训）
- 一开始按官方文档的默认写法建 RLS：`TO authenticated, anon` + `WITH CHECK (owner_id = auth.uid())`。
  **实测未登录仍然能写入成功** —— 因为在这个环境里 **`auth.uid()` 对匿名调用返回的是字符串 `'anon'`，
  而不是 NULL**，于是 `owner_id = auth.uid()` 变成 `'anon' = 'anon'` 恒真。
  后果：任何访客写进同一个匿名桶，而且 SELECT 策略同样恒真 → **匿名之间互相能读到对方的数据**。
- 正确做法：**策略与 GRANT 都只给 `authenticated`**，把 `anon` 彻底排除；再 REVOKE 掉 anon 的表权限。
  改完实测：匿名 INSERT / SELECT / UPDATE / DELETE 全部 `42501 permission denied for table saves`。
- 顺带：`db_list_rls` 返回的 `Roles` 字段**永远是空字符串**，看不出授权对象 ——
  **验证权限只能靠真实请求打一发**，不能信这个字段。
- 结论：凡是"用户私有数据"的表，一律只授 `authenticated`；这条要写进以后所有新表的建表模板。
