## 数境169 · 平板掉帧定位与修复（用户："vivo Pad 2 拖摇杆卡顿，X90 Pro 和电脑都流畅"）

### 先算账（结论：不是平板弱，是工作量差 4~5 倍）
| | vivo Pad 2 | vivo X90 Pro |
|---|---|---|
| 屏幕 | 12.1" 2800×1968 @144Hz LCD | 6.78" 2800×1260 @120Hz AMOLED |
| SoC/GPU | 天玑9000 / Mali-G710 MC10 | 天玑9200 / Immortalis-G715 MC11 |
| 游戏后备画布 | **2800×1968 = 551 万像素** | **786×1750 = 138 万像素** |
| 每帧预算 | 6.94ms | 8.33ms |

- 根因：`DPR=Math.min(devicePixelRatio||1,2)` **只保护了手机** ——
  手机要维持 ~393dp 宽，dpr 必然 ≈3.2 → 被压到 2（= 只用 62% 分辨率渲染，这才是手机一直流畅的隐藏原因）；
  平板 dpr 本来就是 2，**压不动** → 满原生分辨率，主线程光栅化的活是手机的 4.0 倍，
  再乘 144/120 = **每秒 4.8 倍**，偏偏每帧预算少 17%。
- LCD 暗场拖影 + 12.1" 大屏角速度放大，是"看起来更卡"的次要原因。

### 改的三处 + 一个角标
1. **自适应分辨率**（`36_loop.js` 顶部 `PIX_BUDGET=1800000`）：
   `DPR=clamp(sqrt(PIX_BUDGET/(VW*VH)),1,min(dpr,2))`。手机 430×932 → dpr 仍 2（一分不降）；
   平板 1400×984 → dpr 1.14、画布 1600×1124（181 万，工作量 −66%）。
2. **渲染节拍器**：`loop()` 不再直接 draw()，走 `paceProbe(dt)` + `paceDraw(now)`。
   按 **vsync 整数倍**抽帧（144Hz → 144/72/48/36/24），解决「144÷60 除不尽 → 2/3 帧交替」的节奏抖动；
   每 30 帧评档：耗时 >80% 预算或迟到帧 >25% 降档，连续 6 批 <40% 才升档；**hz=0（没量准）时不升降档**。
3. **地形层位移吸附整数设备像素**：`Math.round(-cam.x*SCALE*真实dpr)/真实dpr`（原来 toFixed(2) 带小数）。
4. **`?dbg=1` 角标**（新模块 `src/js/74_dbg.js`，元素+样式都从 JS 注入）：
   屏 / 后备画布 / 实测节拍（非标准值打问号）/ 渲染 fps / rAF fps / 每帧耗时与预算 / 迟到数 / 缩放。

### 实测（软件光栅 + CPU×6，每状态 2~3 轮取最好）
| 平板横屏 | 改动前 | 改动后 |
|---|---|---|
| 地图静止 | 9.1 fps | **15.2 fps**（1.67×） |
| 地图移动中 | 9.4 fps | **16.3 fps**（1.73×） |
| ☰ 菜单 | 59.3 | 59.6 |
| 答题面板 | 19.2 | 18.2（噪声内，走的是 backdrop 模糊那条路） |

- **隔离实验**（同一份代码、同一个页面，只把 DPR 强改回 2）：14.9 → **9.6 fps**；
  而改动前产物在 dpr2 下是 9.4 → 说明节拍器与吸附零开销，涨幅全部来自分辨率。
- **手机竖屏回归**：静止 16.4→17.1 / 移动 17.1→16.5 / 菜单 59.4→59.5 / 答题 51.6→50.5，画布 860×1864 未降 → 零回归。
- 注意：这台模拟机**复现不出 GPU 合成**，绝对帧率偏低，只能比比例；真机上（GPU 合成 + 光栅化才是大头）收益应更大。

## 数境169 · 闯关四国改并联（用户："四个学科从线性串联改为并联结构，可随时传送到任意一国的最起始位置"）

### 摸清现状（先找"锁"到底在哪）
- 四国＝四个学科、各一张独立地图：`NATIONS`（`11_world.js:68`）math/phys/chem/bio，共 14 个域。
- **跨国顺序锁只有一处**：`57_multination.js` 的 `nationUnlocked(n)`（第 92-97 行，"必须拿满上一国全部徽章"），
  且**只被传送网络面板用**（`showNationPortal` 里算 `open` 与渲染锁态文案）——`switchNation` 本身不检查它。
- `BRIDGES[].need` 是**同一国内**的域间门（数学 5 桥需要 `func`/`tri`/`seq`/`geo` 徽章），与国家顺序无关，不动。
- 现成能力全都有：`switchNation` 落地会自动点亮该国第一座塔、`useNation` 各国各记一份坐标、
  `goTotem` 可跳已点亮的塔 —— 所以"并联"基本只是**把门槛拿掉 + 面板改成四国常驻入口**。

### 改了什么
1. **删 `nationUnlocked()`**，换成 `goNationStart(id)`：跨国走 `switchNation(id,true)`；
   本国只把人挪回第一域（不重建地图）。
2. `switchNation(id,atStart)` 加第二参数：`atStart=true` 时落点强制取 `n.regions[0]` 的出生点
   （`useNation` 会把该国上次坐标读回来，必须在它之后覆盖）。
3. 面板（`showNationPortal`）改成"每国一个常驻入口"：🚀 开辟航路 / ↩️ 再次前往 / 🏠 回到出生域 + 已点亮的塔；
   删掉锁态分支与"先通关上一国"文案。
4. 顺带紧凑化：**未点亮的塔从"一座一行"合并成一行「还有 N 座未点亮」** —— 四个国家铺开十几行是这次才暴露的体验问题。
5. 文案：`57` 的 questText（本国全通后改成"传送网络可去其余三国任一"）、`55_boot_news.js` 首次进入说明、
   两处 `showMenu` 模板（49/70）里 🌀 传送阵的说明。
6. **`tools/smoke.py` 新增永久检查「四国直达」**（从别国绕一圈回数学国，逐站验"切过去了+落在出生域+第一座塔亮着"，
   并检查面板里没有锁）。注意：本国→本国不算切换，所以循环要从 `NATIONS.slice(1).concat([NATIONS[0]])` 开始。
